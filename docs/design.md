# FinPilot v1: дизайн проекта (устарел — актуальная версия в docs/spec.md)

Трек: **AI + Finance**. Хакатон Veritas AI 2026. Сдача: **вс 15 ноября, 23:59 ET**.

> This project is a prototype and is not financial advice.

## Главная мысль (одна, для жюри)
**FinPilot останавливает покупку, которая сломает цель вашей семьи, *до* того, как вы нажали «Купить».**

## Клиент
Семья, которая копит на цель (учёба ребёнка, машина, дом) и не понимает, куда уходит доход.
Только семьи. Малый бизнес — в «Что дальше».

## Продукт
- **Сайт (платформа):** подключение PayPal Sandbox или демо-данных → траты по категориям → бюджет и цели → чат с ассистентом.
- **Память платформы:** профиль семьи, бюджеты, цели (сумма, срок), транзакции с категориями (с исправлениями), прогнозы, отложенные покупки.
- **Расширение Chrome:** на странице товара любого магазина читает название и цену (schema.org / og-теги → запасные селекторы Amazon → выделение мышкой) → `POST /check-purchase` → 🟢 / 🟡 / 🔴 и одно предложение почему. Кнопки «Отложить» (в память) и «Спросить ассистента».
- **Единый ассистент** на сайте и в расширении, без платного API: классификатор намерений (~6 штук) → параметры кодом → ответ по шаблону с цифрами из базы. Цифры всегда считает код.

```
PayPal Sandbox / демо ─► импорт ─► SQLite (память) ◄─ FastAPI ─┬─► сайт (HTML + Tailwind + Chart.js)
                                       ▲                       └─► расширение Chrome (MV3)
                         ML: категории · перерасход · намерения
```

## ML и проверка
| # | Задача | Модель | Baseline | Метрика |
|---|---|---|---|---|
| 1 | **Категоризация** трат и товаров + дообучение на исправлениях | TF-IDF (символы) + LR | ключевые слова; самая частая категория | macro-F1 на **другом** датасете; кривая «0/10/50/200 исправлений» |
| 2 | **Перерасход:** на день *d* месяца — выйдет ли семья за свой обычный уровень трат по категории к концу месяца | градиентный бустинг | экстраполяция «потрачено × 30/d» | precision/recall, калибровка; тест — последние месяцы |
| 3 | **Бэктест решения «купить / отложить»** на реальных покупках семей из датасета | правило поверх ML 2 | без расширения; правило 50/30/20; решение поверх экстраполяции | precision/recall 🔴; **сколько $ перерасхода можно было избежать**, на сколько месяцев раньше цель |
| 4 | **Намерения ассистента** | TF-IDF + LR | ключевые слова | macro-F1 на вопросах, написанных командой |

Разбор ошибок: минимум 3 конкретных примера (покупка, где модель ошиблась, и почему).

## Проверка по критериям жюри
- **Technical quality:** baseline у каждой модели, тест по времени, категоризация на чужом датасете, бэктест самого решения, разбор ошибок. Честно: данные семей синтетические.
- **Impact:** одна цифра в деньгах из бэктеста + 2–3 факта о проблеме с источниками.
- **Creativity:** не очередной дашборд, а решение в момент покупки, на любом сайте, по прогнозу и памяти о цели.
- **Clarity:** одна история в демо: цель «учёба» → товар на Amazon → 🔴 → «Отложить» → цель не сдвинулась.

## Журнал выполнения

### Шаг 1. Данные ✅ (`ml/data_prep.py`, `ml/categories.py`)
- 16 единых категорий; таблицы сопоставления для обоих датасетов.
- Обучение: 68 000 строк выписок (DoDataThings). Семьи: 148 936 транзакций, 100 семей, у 97,9% есть единая категория (снятие наличных, благотворительность, налоги, возвраты, кредиты исключены из теста категоризации).
- Имена и email семей не используем.
- LightGBM не запускается без Homebrew → градиентный бустинг из scikit-learn (`HistGradientBoosting`).

### Шаг 2. Категоризация ✅ (`ml/train_categorizer.py`, результаты в `ml/results/categorizer.json`)
- Чистка текста (`ml/text_utils.py`): убираем банковские обёртки («Card Purchase 10/08 … Card 1693», «CHECKCARD»), номера и даты.
- Честная схема: модель учится только на DoDataThings. Семьи делим пополам: 50 для настройки (dev) и исправлений, 50 только для итогового теста.

| Тест: 50 семей, 63 974 транзакции | macro-F1 |
|---|---|
| Самая частая категория | 0,002 |
| Ключевые слова | 0,650 |
| **Модель (TF-IDF + LR), без единого примера из данных семей** | **0,692** |
| Модель + 10 исправлений пользователей | 0,710 |
| Модель + 50 исправлений | 0,743 |
| Модель + 200 исправлений | **0,836** |

- Исправления берутся из dev-семей (по одному на продавца), тестируются на других семьях.
- Слабые места модели: развлечения, путешествия, образование/детский сад (в обучении другие названия продавцов). Ключевые слова здесь иногда лучше.
- Главные ошибки: входящие переводы Zelle → «доход»; транспортные карты (Ventra) → «развлечения»; салоны красоты через Square («SQ *…») → «еда».

### Шаг 3. Прогноз перерасхода ✅ (`ml/overspend_features.py`, `ml/train_overspend.py`, результаты в `ml/results/overspend.json`)
- Вопрос: на 5/10/15/20/25-й день месяца — закончит ли семья месяц выше своей нормы по категории?
  Норма = медиана трат за предыдущие 6 месяцев; перерасход = больше нормы на 10%+.
- 9 категорий трат. Разбиение по времени: обучение 2025-01…2025-12, выбор порога 2026-01…03, **тест 2026-04…09** (17 030 примеров, перерасход в 39,5%).
- Модель: градиентный бустинг (scikit-learn) с ограничением «чем больше потратил, тем выше риск» (монотонность).

| Тест (апр–сен 2026) | Precision | Recall | F1 | PR-AUC |
|---|---|---|---|---|
| Пропорция «потрачено × 30/d» | 0,686 | 0,676 | 0,681 | 0,754 |
| Темп «потрачено + что обычно уходит позже» | 0,677 | 0,742 | 0,708 | 0,742 |
| **Модель** | **0,774** | **0,690** | **0,729** | **0,853** |

- Главный выигрыш — **в начале месяца**, когда предупреждение полезнее всего: на 5-й день модель ловит 55% перерасходов (точность 62%), пропорция — 45% (точность 59%).
- Исправлена ошибка: в обучении терялся доход за месяцы, где он приходил после 25-го числа; живой расчёт признаков (`ml/live_features.py`) теперь совпадает с обучением (`ml/check_live_features.py`).
- Калибровка хорошая: когда модель говорит ~25%, перерасход случается в 25% случаев; в диапазоне 0,6–0,9 модель немного переоценивает риск.
- Ошибки для отчёта:
  - пропуск: к 25-му числу на продукты потрачено $7,50 при норме $555, а за последние 5 дней — $603 (одна большая закупка, предсказать нельзя);
  - ложная тревога: к 10-му числу на покупки $2 388 при норме $1 598, но потом вернули товары, и месяц закончился на $1 744 (возвраты модель не предвидит).

### Шаг 4. Бэктест «купить / отложить» ✅ (`ml/backtest.py`, результаты в `ml/results/backtest.json`)
- Переигрываем **4 033 онлайн-покупки от $20** у 83 семей в тестовых месяцах (апр–сен 2026), как будто расширение было открыто при оплате.
- «Вредная» покупка = её категория закончила месяц выше нормы на 10%+ (52,6% покупок).
- «Избежали перерасхода» = сколько перерасхода покрывают отложенные покупки (их переносят на следующий месяц; ниже нуля перерасход не уменьшается).
- **Честное сравнение — одинаковое число предупреждений:** каждый метод откладывает свои самые рискованные покупки.

| Откладываем | Правило 50/30/20 | Пропорция | **Модель** |
|---|---|---|---|
| 10% покупок | $124 / семья-месяц, точность 0,68 | $185, точность 0,85 | **$203, точность 0,99** |
| 20% покупок | $230, точность 0,62 | $259, точность 0,82 | **$305, точность 0,99** |
| 30% покупок | $291, точность 0,58 | $320, точность 0,81 | **$360, точность 0,96** |

- При своих «родных» порогах пропорция откладывает 63% покупок, модель 56%; денег экономят почти поровну ($421 и $411 на семью в месяц), но у модели на 30% меньше ложных тревог (481 против 682).
- **Решение для расширения:** 🔴 «лучше отложить» — вероятность ≥ 0,75 (самые рискованные ~20% ситуаций на валидации), 🟡 «подумай» — ≥ 0,44 (порог модели), иначе 🟢.
- Честные оговорки: (1) отложенная покупка переносится, а не исчезает — мы считаем перенос перерасхода, а не навсегда сэкономленные деньги; (2) высокая точность верхних 10% частично объясняется покупками в конце месяца, когда семья уже вышла за норму — там предупреждение очевидно, но всё равно полезно; (3) мы не моделируем, как отложенная покупка меняет следующие решения.
- Ошибки для отчёта:
  - ложная тревога: в мае семья к 7-му числу уже потратила на покупки больше нормы; модель откладывает Amazon $169, Nordstrom $110, Chewy $132 с вероятностью ~100%, но потом возвраты опускают месяц до $1 744 при норме $1 598 (меньше +10%);
  - пропуск: Netflix $29 (подписка подорожала — модель не знает о повышении цены), Amazon $39 и Lyft $61 в середине месяца, где риск выглядел низким (~3%).

### Шаг 5. Бэкенд ✅ (`backend/`)
- FastAPI + SQLite (`finpilot.db`, не коммитится). Запуск: `.venv/bin/uvicorn backend.main:app --reload --port 8000`, документация API: `/docs`.
- Память платформы: транзакции (категория от модели или от пользователя), исправления по продавцу, цели, бюджеты, отложенные покупки, профиль.
- Источники: демо-семья (misata C000369: двое детей, доход $117 700) и PayPal Sandbox (Transaction Search API).
  Категории демо-семьи ставит **наша модель**, не датасет (совпадение с разметкой датасета 85%).
- Демо-«сегодня»: месяц 2026-08 датасета показывается как текущий (к середине месяца на покупки уже $647 из обычных $973).
- Эндпоинты: `/api/status`, `/api/import/demo`, `/api/import/paypal`, `/api/summary`, `/api/transactions`,
  `/api/transactions/{id}/category` (исправление → все транзакции этого продавца + дообучение в фоне),
  `/api/budgets/{category}`, `/api/goals`, `/api/check-purchase`, `/api/postpone`, `/api/postponed`.
- Деньги считает код: свободные деньги = доход − траты − переводы другим людям (переводы между своими счетами определяются по паре одинаковых сумм); цели получают деньги по очереди сроков, прогноз даты — помесячной симуляцией.
- Проверка демо: наушники Sony $348 на Amazon → 🔴 «Покупки: $647 из обычных $973. С этой покупкой шанс перерасхода растёт с 72% до 95%. Цель "Kids' college fund" сдвинется примерно на 13 дней. Лучше отложить до следующего месяца».

### Шаг 6. Сайт ✅ (`web/`)
- Одна страница (HTML + Tailwind + Chart.js), отдаётся тем же FastAPI: `http://localhost:8000`.
- Разделы: подключение (PayPal Sandbox / демо-семья) → «Этот месяц» (траты, доход, свободные деньги, риск перерасхода по категориям от ML, свой бюджет по клику) → график за 6 месяцев → цели (сколько нужно, сколько получает, когда достигнем) → отложенные покупки → транзакции с исправлением категории → ручная проверка покупки → чат ассистента (ответы появятся на шаге 8).
- PayPal Sandbox: вход и импорт работают (в тестовом аккаунте пока одна транзакция — стартовый баланс).

### Шаг 7. Расширение Chrome ✅ (`extension/`)
- Manifest V3. Поиск товара (`detect.js`): schema.org Product → мета-теги цены → вёрстка Amazon → microdata; запасной путь — ввести цену в окне расширения или выделить цену → правый клик → «Check this price with FinPilot».
- Карточка на странице (`content.js`, Shadow DOM, не ломает стили магазина): 🟢 свёрнута в значок, 🟡/🔴 раскрыта; причина, шанс перерасхода до/после, кнопки «Postpone», «Ask assistant», «Buy anyway».
- С платформой общается только фоновый воркер (`background.js`), адрес настраивается в окне расширения.
- Категория товара: магазин (doordash → еда, booking → путешествия…) → слова в названии → по умолчанию «Покупки». Модель категоризации обучена на банковских строках и на названиях товаров ошибалась (наушники → «Транспорт»), поэтому для товаров — правила.
- Проверено на локальной тестовой странице `web/demo-product.html`: товар найден, вердикт 🔴 (шанс 72% → 95%), «Postpone» сохраняется на платформе. Разбор цен: «$1,299.99», «1.299,99 €», «12 990 ₸», «£7.5» — верно.
- Установка: `chrome://extensions` → Developer mode → Load unpacked → папка `extension/`.

### Шаг 8. Ассистент ✅ (`ml/intents.py`, `ml/train_intent.py`, `backend/assistant.py`, `/api/chat`)
- Один ассистент для сайта и расширения, без платного API: ML-классификатор намерений (TF-IDF + LR, 7 намерений) → параметры из текста кодом (категория, месяц, сумма) → ответ по шаблону с цифрами из базы.
- Обучение: 346 фраз из шаблонов. Тест: 43 вопроса, написанных отдельно другими словами (команде стоит добавить свои в `TEST_QUESTIONS`).

| Тест (43 вопроса) | Accuracy | Macro-F1 |
|---|---|---|
| Ключевые слова | 0,581 | 0,627 |
| **Модель** | **0,744** | **0,716** |

- Ошибки модели для отчёта: «good morning» → «можно ли купить»; «how do we cut costs» → «цели»; «things i put off buying» → «можно ли купить» (вместо «отложенные»). Ключевые слова не понимают фразы без своих слов: «thinking about a $600 ipad, good idea?».
- Если модель не уверена (< 35%), ассистент показывает подсказку, а не гадает.
- Из расширения ассистент знает товар на странице: «what if I wait until payday?» → «Купить сейчас: 95% шанс перерасхода. Если подождать до 1 декабря, покупка займёт 36% обычного бюджета на покупки».
