# FinPilot: дизайн проекта (рабочее название)

Трек: **AI + Finance**. Хакатон Veritas AI 2026. Сдача: **вс 15 ноября, 23:59 ET**.

> This project is a prototype and is not financial advice.

## Главная мысль (одна, для жюри)
**FinPilot останавливает покупку, которая сломает цель вашей семьи, *до* того, как вы нажали «Купить».**

## Клиент
Семья, которая копит на цель (учёба ребёнка, машина, дом) и не понимает, куда уходит доход.
Только семьи. Малый бизнес — в «Что дальше».

## Продукт
- **Сайт (платформа):** подключение PayPal Sandbox или демо-данных → траты по категориям → бюджет и цели → чат с ассистентом.
- **Память платформы:** профиль семьи, бюджеты, цели (сумма, срок), транзакции с категориями (с исправлениями), прогнозы, отложенные покупки.
- **Расширение Chrome:** на странице товара любого магазина читает название и цену (schema.org / og-теги → запасные селекторы Amazon → выделение мышкой) → `POST /check-purchase` → 🟢 / 🟡 / 🔴 и одно предложение почему. Кнопки «Отложить» (в память) и «Спросить ассистента».
- **Единый ассистент** на сайте и в расширении, без платного API: классификатор намерений (~6 штук) → параметры кодом → ответ по шаблону с цифрами из базы. Цифры всегда считает код.

```
PayPal Sandbox / демо ─► импорт ─► SQLite (память) ◄─ FastAPI ─┬─► сайт (HTML + Tailwind + Chart.js)
                                       ▲                       └─► расширение Chrome (MV3)
                         ML: категории · перерасход · намерения
```

## ML и проверка
| # | Задача | Модель | Baseline | Метрика |
|---|---|---|---|---|
| 1 | **Категоризация** трат и товаров + дообучение на исправлениях | TF-IDF (символы) + LR | ключевые слова; самая частая категория | macro-F1 на **другом** датасете; кривая «0/10/50/200 исправлений» |
| 2 | **Перерасход:** на день *d* месяца — выйдет ли семья за свой обычный уровень трат по категории к концу месяца | градиентный бустинг | экстраполяция «потрачено × 30/d» | precision/recall, калибровка; тест — последние месяцы |
| 3 | **Бэктест решения «купить / отложить»** на реальных покупках семей из датасета | правило поверх ML 2 | без расширения; правило 50/30/20; решение поверх экстраполяции | precision/recall 🔴; **сколько $ перерасхода можно было избежать**, на сколько месяцев раньше цель |
| 4 | **Намерения ассистента** | TF-IDF + LR | ключевые слова | macro-F1 на вопросах, написанных командой |

Разбор ошибок: минимум 3 конкретных примера (покупка, где модель ошиблась, и почему).

## Проверка по критериям жюри
- **Technical quality:** baseline у каждой модели, тест по времени, категоризация на чужом датасете, бэктест самого решения, разбор ошибок. Честно: данные семей синтетические.
- **Impact:** одна цифра в деньгах из бэктеста + 2–3 факта о проблеме с источниками.
- **Creativity:** не очередной дашборд, а решение в момент покупки, на любом сайте, по прогнозу и памяти о цели.
- **Clarity:** одна история в демо: цель «учёба» → товар на Amazon → 🔴 → «Отложить» → цель не сдвинулась.

## Журнал выполнения

### Шаг 1. Данные ✅ (`ml/data_prep.py`, `ml/categories.py`)
- 16 единых категорий; таблицы сопоставления для обоих датасетов.
- Обучение: 68 000 строк выписок (DoDataThings). Семьи: 148 936 транзакций, 100 семей, у 97,9% есть единая категория (снятие наличных, благотворительность, налоги, возвраты, кредиты исключены из теста категоризации).
- Имена и email семей не используем.
- LightGBM не запускается без Homebrew → градиентный бустинг из scikit-learn (`HistGradientBoosting`).

### Шаг 2. Категоризация ✅ (`ml/train_categorizer.py`, результаты в `ml/results/categorizer.json`)
- Чистка текста (`ml/text_utils.py`): убираем банковские обёртки («Card Purchase 10/08 … Card 1693», «CHECKCARD»), номера и даты.
- Честная схема: модель учится только на DoDataThings. Семьи делим пополам: 50 для настройки (dev) и исправлений, 50 только для итогового теста.

| Тест: 50 семей, 63 974 транзакции | macro-F1 |
|---|---|
| Самая частая категория | 0,002 |
| Ключевые слова | 0,650 |
| **Модель (TF-IDF + LR), без единого примера из данных семей** | **0,692** |
| Модель + 10 исправлений пользователей | 0,710 |
| Модель + 50 исправлений | 0,743 |
| Модель + 200 исправлений | **0,836** |

- Исправления берутся из dev-семей (по одному на продавца), тестируются на других семьях.
- Слабые места модели: развлечения, путешествия, образование/детский сад (в обучении другие названия продавцов). Ключевые слова здесь иногда лучше.
- Главные ошибки: входящие переводы Zelle → «доход»; транспортные карты (Ventra) → «развлечения»; салоны красоты через Square («SQ *…») → «еда».

### Шаг 3. Прогноз перерасхода ✅ (`ml/overspend_features.py`, `ml/train_overspend.py`, результаты в `ml/results/overspend.json`)
- Вопрос: на 5/10/15/20/25-й день месяца — закончит ли семья месяц выше своей нормы по категории?
  Норма = медиана трат за предыдущие 6 месяцев; перерасход = больше нормы на 10%+.
- 9 категорий трат. Разбиение по времени: обучение 2025-01…2025-12, выбор порога 2026-01…03, **тест 2026-04…09** (17 030 примеров, перерасход в 39,5%).
- Модель: градиентный бустинг (scikit-learn) с ограничением «чем больше потратил, тем выше риск» (монотонность).

| Тест (апр–сен 2026) | Precision | Recall | F1 | PR-AUC |
|---|---|---|---|---|
| Пропорция «потрачено × 30/d» | 0,686 | 0,676 | 0,681 | 0,754 |
| Темп «потрачено + что обычно уходит позже» | 0,677 | 0,742 | 0,708 | 0,742 |
| **Модель** | **0,727** | **0,734** | **0,730** | **0,855** |

- Главный выигрыш — **в начале месяца**, когда предупреждение полезнее всего: на 5-й день модель ловит 65% перерасходов, пропорция — 45%.
- Калибровка хорошая: когда модель говорит ~25%, перерасход случается в 25% случаев; в диапазоне 0,6–0,9 модель немного переоценивает риск.
- Ошибки для отчёта:
  - пропуск: к 25-му числу на продукты потрачено $7,50 при норме $555, а за последние 5 дней — $603 (одна большая закупка, предсказать нельзя);
  - ложная тревога: к 10-му числу на покупки $2 388 при норме $1 598, но потом вернули товары, и месяц закончился на $1 744 (возвраты модель не предвидит).
